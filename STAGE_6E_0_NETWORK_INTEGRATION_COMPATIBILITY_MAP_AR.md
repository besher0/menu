## 6. ترتيب مقترح لدمج Network مع Dashboard الأحدث — **دراسة لا تنفيذ**

1. **استلام نسخة Dashboard الأحدث المعيّنة بالـCommit أو Developer Golden Master** مع Screen/Component/State/Field Ownership/Navigation/Capability/Permission/Validation maps المنصوص عليها في Ledger V62.4. قارنها أولًا بمرجع HTML V62.4 وبمحرر Git الحالي؛ لا تُفسر غياب الكود الأحدث كتوافق. هذه الخطوة لا تحتاج DB.
2. **مطابقة قاموس الهويات والملكية**: ما معنى Business/Market/Outlet/Restaurant/Branch في Dashboard الجديد؟ أين تعيش Product/Category/Node stable IDs؟ ما الذي يمثل Local/Inherited/Removed/Revert؟ حسم هذه الخريطة قبل أي Schema أو نقل بيانات. امنع chain→single flatten وتغيير IDs تلقائيًا.
3. **مطابقة عقود التحرير والصلاحيات والقدرات**: حقول Business الثابتة مقابل Outlet overlay، structural edit مقابل local price/availability، Package per Outlet وAction Required عند الفقد. قارن API/DTO الحالية (`expectedVersion`, full Tree) بحالات editor الجديدة قبل اقتراح Overlay write API؛ لا ترسل Effective Tree كاملة إلى canonical PUT.
4. **تصميم قراءة Effective Outlet أولًا على الورق وباختبارات تعاقدية لاحقة**: Business canonical + tombstones/local nodes/ordering + mode/schedule/availability/capability + Linked same-Outlet closure، مع ثبات IDs وCycle/tenant/Market boundaries. حدّد Revision مركبة/سياق Cart/Quote/Snapshot ولا تعتمد `configurationVersion` الوحيدة باعتبارها كافية بلا إثبات.
5. **مراجعة التسعير والـMinimum والـCart على هذا السياق** باستخدام Shared Engine نفسه بعد إثبات ملاءمة Effective Tree؛ لا تبتكر Pricing Engine ثانيًا. اختبر ORIGINAL live وCUSTOM local وIncluded Quantity وnull/zero وService Mode/Size وrequired unsatisfiability؛ أدرج دلالات Translation/Locale.
